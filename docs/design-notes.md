# 设计取舍与已知局限

## 1. 把"写作"拆成状态机，而不是一次生成

一次性生成整篇论文的问题不是质量差，而是**无法定位错误**：数字错了、结论强了、图注夸大了，全混在一段文字里。拆成阶段后，每一段产出都有明确的输入和验收条件，出错时可以回到具体门控重做。

代价是流程变重。对一个三千字的短文，这套流程明显过度；它的适用对象是有多个分析、多个图表、要投英文期刊、还要返修的稿件。

## 2. 门控交给作者，模型只准备材料

模型可以判断"数字是否可追溯到文件"，不能判断"这个结论是否值得发表"。因此所有 Gate 的批准权留在作者手里，模块的职责是把待批材料准备到"只需看一眼就能决定"的程度。这也是为什么 `check_gates.py` 只做只读报告，并且明确写着"退出码 0 不代表批准"。

## 3. 语言层必须晚于科学层

先润色再核对数字，会让每一轮润色都成为一次潜在的数字漂移源。流程因此强制 G3 之后才允许语言层运行，并要求语言层输出"未修改的科学内容声明"。这一条最容易被绕过，也最值得坚持。

## 4. 反 AI 味不做同义词替换

`scientific-prose` 与 `lieflat-less-ai-tone` 都采用白名单式改写：只有命中具体规则才动，没命中就逐字保留。原因是同义词替换式的"humanize"（把 associated with 换成 linked to）既改变不了文风，还会破坏术语一致性。真正的 AI 味来自模板化句式和过度总结，不来自个别词。

## 5. 不确定性表达按类型分开命名

系数置信区间、bootstrap 区间、模型间离散度、情景范围是四种东西，合成"总不确定性"会让读者误读成预测区间。流程要求在 `figures.yml` 和 `results.yml` 中分别记录，并在图注中按来源命名。

## 6. 报告必须绑定输入版本

同一份"已核验"报告，在输入文件变了之后就不再有效。因此报告要求写 SHA256 与核验时间，输入变化即重核受影响结论。这条规则的成本是重复劳动，收益是避免"我们查过"变成一句无法追溯的话。

## 已知局限

- **依赖登记册质量**：登记册本身错了，后面的检查都会一致地错。它拦数字漂移，不拦科学判断错误。
- **不替代领域专家**：`causal-inference-audit` 与 `climate-counterfactual-audit` 只做边界检查，不能判断识别策略在该领域是否站得住。
- **期刊规则会过期**：`journal.yml` 的 `verified` 有核验日期，投稿前需重新确认，尤其字数与图表限制。
- **对中文期刊适配较弱**：当前模板假设英文稿件为主，中文期刊的结构与引用规范需要另行补充。
- **不是投稿系统**：不代替投稿平台、不处理版权与署名协议，实际提交必须由作者执行。
