# 模块契约

各模块先读 `paper.yml`、`workflow.yml` 及任务相关的登记册。既有模块中的审批前置限制只限制下游正式产出，不阻止准备审批所需的核验与报告。

| 模块 | 输入 → 输出 | 写入边界 |
|---|---|---|
| paper-bootstrap | 文件盘点 → 来源清单、冲突与候选登记册 | 不覆盖已锁定登记，不写正文 |
| scientific-architecture | 问题/证据 → Q–M–R–C–图表映射及扩展提纲 | 架构候选需 G1，不补造结论 |
| evidence-lock | 原始输出、登记册、审计发现 → 数值绑定及 G2 材料 | 核实后更新登记册，不自批 |
| statistical-results-lock | 输出与统计口径 → 数字/单位/CI/模型一致性报告 | 只读 |
| causal-inference-audit | 设计与主张 → 推断边界和措辞风险 | 只读，不把锁定解释为科学有效 |
| climate-counterfactual-audit | 反事实/情景方法与输出 → 可比性与不确定性报告 | 只读 |
| evidence-drafting | 已批准结论和结果 → 正文或逐条修订 | 不改数字、模型、结论强度；修订仅执行 G4 接受项 |
| methods-results-alignment | 方法/结果/图表 → 双向覆盖及缺失项 | 不替作者通过 G3 |
| scientific-prose | G3 后稳定文本 → 润色稿与实质变更说明 | 保留数字、限定词、术语、引用与结论强度 |
| anti-defensive-writing | G3 后英文正文 → 直接表达贡献、压缩重复辩解的修订 | 保留影响结论的不利结果与必要推断条件；与 scientific-prose 组合 |
| lieflat-less-ai-tone | 正文及提要 → 编号规则命中修订或不修改记录 | 结构、事实、限定和未命中文字不变 |
| reviewer-red-team | 全文与登记册 → 有定位和证据的意见表 | 只评论，用户作 G4 决定 |
| journal-adapter | 官方作者指南 → 有 URL、文章类型、查验日期的 journal.yml 与适配稿 | 无法查证标 unverified；不得套用其他期刊规则 |
| submission-audit | 投稿材料及期刊规则 → blocker/缺项/通过证据 | 仅审计；不提交、不自批 G5/G6 |
| figure-planner | 已有主张/证据 → 图与 panel 计划、图注—Results 对应 | 先规划；绘图交由外部绘图能力执行 |
| figure-legend | 实际图件、统计输出与目标期刊规则 → 可用图注或定位审核 | 保留数值、样本、区间类型及比较方向；不补造检验，不重绘；同步受影响正文/SI 引用 |
| citation-verifier | 引用与来源 → 本地/身份/支持关系三层报告 | 默认只读；格式交 journal-adapter |
| rebuttal-response | 审稿意见与当前材料 → 子问题矩阵、回复候选及实际改稿对应 | 不代作 G4 决定，不虚报新分析 |

## 与外部能力衔接

- 科研图：需要制作或修改论文图时，使用当前环境可用的绘图技能或脚本；图号、图注和证据绑定仍由本工作流维护，不复制第二套绘图规则。
- 同行评审：`reviewer-red-team` 可调用可用的评审类技能组织意见，但保持只评论、由作者作 G4 处置的边界。未审阅的材料写“未评估”，不推测编辑决定。
- DOCX/PDF：需读写或验证版式时使用对应文档技能，正文科学约束仍然优先。
- 文献核验：`citation-verifier` 执行本地/身份/支持三层检查，`journal-adapter` 管格式，`submission-audit` 汇总覆盖与阻塞项。DOI 可解析不等于支持结论；无全文须注明覆盖限制。

所有外部技能仅在可用且任务确实需要时读取；缺失时报告能力缺口，不虚称已经执行。

## 证据冲突规则

文件格式不是权威等级：CSV 与文稿不一致时，先查版本、样本、模型和验收来源，不能因为格式“更底层”就自动覆盖。

哈希只证明文件身份，不证明分析正确。禁止从旧稿倒填“核验值”。

局部修订后只检查受影响的主张、结果、方法、图表、引用和下游段落；无关且已核验的内容不必全部重跑。
