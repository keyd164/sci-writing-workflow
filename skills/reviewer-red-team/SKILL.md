# 审稿红队

## 职责

以四个审稿人视角攻击稿件，只输出评论，不改一个字。由作者决定接受哪些意见，再进入修订。

## 前置

- 全文红队通常在语言层完成后进行；用户要求提前审查时可以做局部评审，但须明确覆盖范围，不标记“全篇红队完成”。
- 读 `manuscript/` 全文 + `claims.yml` + `results.yml` + `methods.yml` + `decisions.yml`。

## 四个审稿人

### A — 科学有效性
- 这个分析真的能支持这个结论吗？（claim–evidence 匹配）
- 有没有结论先行：摘要或结论预写了没有数据支持的命题？
- 衍生结论（条件对比、情景翻译）依赖的假设是否显式写出？

### B — 研究设计与统计
- 暴露、结局、混杂的定义与测量
- 固定效应、趋势项、滞后项、前置检验的解释边界
- 生态学谬误等跨层推断是否有防护语句
- 多重比较、样本删除、推断约定（聚类自由度、稳健标准误误用）
- 上游数据的既有误差是否被当成回归不确定性

### C — 领域方法与外推
- 反事实或情景的构造方式是否可复现，单成员/单模型限制是否说明
- 偏差订正、阈值重算、成员匹配、时间窗口定义是否一致
- 参数跨时期可迁移假设是否检验；显著的前置检验对长期外推意味着什么
- 模型离散度是否被当成预测区间

### D — 期刊编辑
- novelty 是否足够、scope 是否匹配目标刊物
- framing 是否在 Introduction 前两句完成；是否会被 desk-reject
- 图表是否服务于故事线；补充材料是否过载
- 标题与摘要是否过度声称

## 输出格式

```
## 红队报告（只读评论）
### A. 科学有效性
- A1 [severity: major/minor] <意见> <位置> <建议动作>
### B. 设计与统计
...
### D. 编辑视角
...
## 逐条意见表
| # | 审稿人 | severity | 位置 | 意见摘要 | 建议动作 |
```

severity：major（不修难以送审）/ minor（应修）/ nit（可选）。

## 规则

- 每条意见必须可定位（章节/段落/句）。
- 不直接改稿；只给建议动作。
- 发现 claims / decisions 层问题 → 标记“约束层问题”单独呈报，不在稿件层处理。
- 报告交作者作 G4 逐条决定；批准前可以补证据，不修改稿件。

## 禁止

- 修改稿件。
- 代替作者决定接受哪些意见。
- 输出无定位的泛泛评论（“写得不够好”这一类）。
